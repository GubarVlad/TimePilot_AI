# TimePilot AI — адаптивный AI-планировщик

Первая полноценная MVP-версия TimePilot AI. Один лёгкий Python-сервер, один HTML-файл, без npm, Docker, FastAPI, PostgreSQL, Google Calendar и Zetaris. Все AI-вычисления выполняются через облачный NVIDIA API; локально модель не запускается.

## Что умеет

- **Главный рабочий экран:** календарь слева, AI-агент с историей диалога справа; на узком экране колонки складываются вертикально.
- Переключение между дневным и недельным календарём, выбор даты, просмотр записей и свободных промежутков.
- Полный CRUD для обычных календарных записей: создать, открыть редактор, изменить поля, дублировать и удалить запись.
- В редакторе доступны название, дата, начало, окончание, приоритет, тип, статус, описание и закрепление времени.
- Проверка пересечений при создании и редактировании; конфликт не применяет частичные изменения.
- AI-агент обрабатывает естественные русские запросы на создание, перенос, редактирование, удаление, анализ нагрузки, поиск свободного времени и оптимизацию расписания.
- Редактирование по отдельным полям: название/описание, дата/время, продолжительность, приоритет, тип, статус и закрепление. Неуказанные поля не должны меняться.
- Перенос только по времени сохраняет исходную дату и длительность; перенос только по дате сохраняет время и длительность.
- Неоднозначная запись или недостаток параметров приводит к уточняющему вопросу, а не к случайному изменению.
- Записи к врачу, брони, билеты и другие внешние обязательства защищены: изменение календаря не считается изменением реального бронирования.
- Оптимизация расписания предлагается как план и применяется только после явного подтверждения пользователя.
- События хранятся на сервере в JSON-файле; API-ключ NVIDIA хранится только на сервере.
- Облачный Nemotron для свободного диалога и Parakeet для распознавания речи; локальные LLM не устанавливаются.

**Ограничение:** в текущей схеме нет единой сущности повторяющейся серии. Чтобы получить серию еженедельных событий, пока нужно создавать отдельные записи; редактирование всей серии одним действием не заявляется как поддерживаемая функция.

## 1. Запуск на своём компьютере

Требуется Python 3.10 или новее и подключение к интернету для первой установки клиента NVIDIA STT. Установки модели на компьютер нет — скачивается только библиотека-клиент, сама модель работает на стороне NVIDIA.

**Windows:** распакуй ZIP и дважды нажми `START.bat`. При первом запуске скрипт установит `nvidia-riva-client`; последующие запуски используют уже установленную библиотеку.

**macOS / Linux:** открой терминал в папке проекта и запусти:

```bash
chmod +x start.sh
./start.sh
```

Приложение откроется на `http://127.0.0.1:8765`. Для доступа к микрофону из удалённой сети сайт должен быть опубликован через HTTPS; `localhost` также считается безопасным контекстом для микрофона.

### Подключить облачный AI — самый простой способ

1. Запусти сайт.
2. Нажми **«Настроить AI»** в верхней панели.
3. Вставь свой NVIDIA API key и нажми **«Сохранить ключ»**.

Ключ сохраняется на сервере в `data/settings.json`, не передаётся обратно в браузер и не добавляется в исходный код. Тот же ключ используется двумя облачными моделями: Nemotron для агента и Parakeet для распознавания речи. В `.gitignore` файл с ключом уже исключён из Git. В архиве нет реальных ключей.

При желании ключ можно настроить и через переменную `NVIDIA_API_KEY` в `.env` или в Environment Variables облачного хостинга. Пример:

```dotenv
NVIDIA_API_KEY=ТВОЙ_КЛЮЧ
NVIDIA_MODEL=nvidia/nemotron-3.5-bolt-e4b
NVIDIA_BASE_URL=https://integrate.api.nvidia.com/v1/chat/completions
```

Если ключ не задан, календарь всё равно работает, а агент поддерживает консервативный набор команд на русском языке, включая некоторые операции редактирования, если запись однозначно названа в кавычках. Для свободного диалога и голосового ввода через Parakeet нужен действительный NVIDIA API key.

### Голосовой ввод (STT)

1. Нажми кнопку микрофона рядом с полем сообщения и разреши доступ к микрофону.
2. Скажи запрос (до 2 минут) и повторно нажми на микрофон, чтобы остановить запись. Запись остановится автоматически через 2 минуты.
3. Время обработки зависит от соединения с NVIDIA. Текст появится в поле ввода — проверь его и нажми отправить агенту.

В браузере аудио записывается как WAV PCM mono, 16-bit, 16 kHz и передаётся на backend. Перед отправкой код удаляет DC-смещение и автоматически усиливает тихий сигнал (без жёсткого RMS-порога, который раньше ошибочно отбрасывал тихую речь). Только цифровой почти нулевой сигнал считается отсутствием аудио. Backend читает WAV и извлекает только raw PCM frames (без RIFF-заголовка), затем вызывает **Parakeet-RNNT 1.1B Multilingual** через NVIDIA Riva gRPC (`grpc.nvcf.nvidia.com:443`, function ID `71203149-d3b7-4460-8231-1be2543a1fca`). Эта функция требует **streaming API**, а не `offline_recognize`; backend отправляет аудио короткими PCM-фрагментами через `streaming_response_generator` и использует `language_code="multi"` для автоопределения поддерживаемого языка, включая русский и нидерландский. Это облачная inference-модель — локально она не запускается. Официальный пример вызова: https://build.nvidia.com/nvidia/parakeet-1_1b-rnnt-multilingual-asr/api.

#### Если голосовой ввод не срабатывает

- После замены архива полностью останови старый сервер (`Ctrl+C`) и запусти новый `START.bat`; старый процесс продолжит использовать старый код.
- В консоли при запуске должна быть строка `STT: Parakeet-RNNT 1.1B Multilingual (streaming)`.
- В настройках AI сохрани NVIDIA API key. Ключ должен иметь доступ к модели Parakeet в NVIDIA API Catalog; ключ для Nemotron не гарантирует, что конкретная STT-функция доступна в аккаунте.
- Запись отправляется как WAV, тихая речь автоматически усиливается, сервер извлекает PCM и передаёт его потоковому gRPC методу модели. Подробная причина ошибки отображается в интерфейсе и в консоли сервера. Если сообщение говорит о «почти нулевом сигнале», browser-запись содержит практически одни нули — выбери правильное устройство ввода в настройках браузера/Windows.
- Если видишь `PERMISSION_DENIED`/`403`, это доступ или ключ, не микрофон. Если `UNIMPLEMENTED` или ошибка метода — убедись, что запускаешь новую версию backend из этого архива.

## 2. Открыть сайт на других устройствах и в разных сетях

`localhost` доступен только на том компьютере, где запущен сервер. Чтобы получить ссылку вида `https://timepilot-ai-....onrender.com`, проект нужно опубликовать в облаке. В архиве есть конфигурация Render.

1. Создай **приватный** репозиторий на GitHub.
2. Загрузи в репозиторий файлы проекта. Не загружай `.env` — он уже внесён в `.gitignore`.
3. Открой [Render Dashboard](https://dashboard.render.com/) и выбери создание **Blueprint**.
4. Подключи свой GitHub-репозиторий. Render прочитает `render.yaml` и создаст web service.
5. Когда Render попросит переменные окружения, заполни `NVIDIA_API_KEY` действительным ключом и `APP_PASSWORD` — новым паролем, который не совпадает с паролем от других сервисов.
6. После успешного Deploy открой адрес `https://<имя-сервиса>.onrender.com`. Этот адрес можно открыть с телефона или компьютера в любой сети; понадобится `APP_PASSWORD`.

**Не публикуй `.env` и не размещай NVIDIA API key в frontend.** Если ключ случайно попал в публичный репозиторий, отзови его и создай новый.

### Важно про бесплатный хостинг и сохранение данных

Файл `data/events.json` — временное хранилище без базы данных, как и просил для первой версии. На бесплатном Render файловая система временная: записи могут исчезнуть после остановки, сна или повторного развёртывания. Сайт и календарь при этом доступны по общей ссылке, пока сервис запущен. Официальная документация Render описывает это ограничение: https://render.com/docs/free и https://render.com/docs/disks.

Если хочешь, чтобы расписание сохранялось на сервере между перезапусками **без PostgreSQL**, используй `render-persistent.yaml`: перед созданием Blueprint переименуй его в `render.yaml`. Эта конфигурация использует persistent disk и платный план Render. Позже хранилище можно заменить на PostgreSQL.

## 3. Использование агента

Примеры запросов:

- `Добавь подготовку отчёта завтра в 14:00 на час, важно`.
- `Переименуй «Подготовка» в «Доклад клиенту»`.
- `Измени описание «Доклад» на «Проверить цифры»`.
- `Перенеси «Доклад» на 15:00` — дата и длительность сохраняются.
- `Перенеси «Доклад» на завтра` — время и длительность сохраняются.
- `Сделай «Доклад» срочным` / `Отметь «Доклад» выполненным`.
- `Продли «Доклад» на 20 минут`.
- `Найди свободные окна на выбранный день`.
- `Оптимизируй расписание на этот день` — сначала предложение, применение только после подтверждения.
- `Удалить «Доклад»?` — вопрос не удаляет запись; команда `Удали «Доклад»` должна однозначно идентифицировать событие.

Для редактирования через запасной режим без API-ключа укажи точное название события в кавычках. Если запись не удаётся однозначно определить или параметр не указан, агент спросит уточнение и не применит догадки. В режиме с NVIDIA AI используется свободный диалог с контекстом недавней переписки, но сервер всё равно проверяет действие перед записью.

## 4. Где хранятся данные

По умолчанию — `data/events.json`. Путь можно изменить переменной `DATA_DIR`. Для облачного persistent disk указан путь `/var/data` в `render-persistent.yaml`. При одновременном использовании несколькими устройствами все браузеры обращаются к одному развёрнутому серверу и видят общий календарь.

## 5. Проверки

```bash
python -m unittest discover -s tests -v
python -m py_compile backend/app.py
```

Backend использует стандартную библиотеку Python для календаря и NVIDIA Riva Client (`nvidia-riva-client`) для облачного распознавания речи. Вызовы NVIDIA API требуют интернет-соединения и действительного ключа. Для AI-агента и STT может действовать лимит API trial endpoint NVIDIA.
## 6. Как агент обрабатывает сложные ситуации

См. [`SCENARIOS.md`](SCENARIOS.md): там описаны классы сценариев для приоритетов, неоднозначных запросов, конфликтов, внешних бронирований, пакетных задач, оптимизации и безопасного подтверждения. Эти правила работают вместе: модель понимает смысл и контекст, а backend повторно проверяет действие и целостность расписания.

**Важно:** никакая система не может буквально заранее перечислить все возможные человеческие формулировки. С API-ключом агент использует облачный Nemotron для свободного диалога; сервер не позволяет модели без проверки менять фиксированные записи, выдумывать успешное внешнее бронирование или молча применять план. Без ключа работает ограниченный режим команд.

Они покрывают календарные CRUD-операции, редактирование отдельных полей, переносы только по дате/времени, конфликтные слоты, приоритеты, неоднозначные запросы, внешние бронирования, подтверждение изменений, оптимизацию, контекст диалога и валидацию голосовых запросов. Реальный NVIDIA API вызов нужно проверить отдельно со своим ключом.


## Актуальная модель агента

По умолчанию используется `nvidia/nemotron-3.5-bolt-e4b` — актуальная стабильная (GA) модель NVIDIA Nemotron 3.5 Bolt E4B, представленная в каталоге NVIDIA 23 октября 2026 года. Модель предназначена в том числе для agentic chat и tool calling; запрос отправляется на официальный OpenAI-compatible Chat Completions endpoint NVIDIA. Для этого backend явно отключает SSE streaming, потому что обработчик агента ожидает один завершённый JSON-ответ. Модель можно переопределить переменной окружения `NVIDIA_MODEL`. Источники: [официальная карточка Nemotron 3.5 Bolt E4B](https://docs.api.nvidia.com/nim/reference/nvidia-nemotron-3_5-bolt-e4b) и [спецификация API Chat Completions](https://docs.api.nvidia.com/nim/reference/nvidia-nemotron-3_5-bolt-e4b-infer).

Перед публичным запуском добавь пароль `APP_PASSWORD`; сам API-ключ не хранится во фронтенде и не должен попадать в ZIP. Совместимость API проверяется локальными тестами с имитацией ответа; реальный вызов NVIDIA требует действительного ключа и не может быть подтверждён без него.


## Структура проекта

- `backend/app.py` — HTTP API, календарная логика, NVIDIA Nemotron и Parakeet STT.
- `backend/requirements.txt` — зависимости backend (включая `nvidia-riva-client`).
- `frontend/index.html` — календарь слева и AI-агент справа; браузерный микрофон и отправка PCM WAV.
- `data/` — локальные `events.json` и `settings.json` (создаются автоматически, в Git/ZIP не включаются).
- `tests/` — автоматические проверки API, редактирования событий и STT.

## Если голосовой ввод не работает

1. Открой приложение через `START.bat` или `start.sh`, а не двойным кликом по HTML.
2. Разреши доступ к микрофону в браузере. Для доступа с другого устройства нужен HTTPS; `localhost` разрешён браузером автоматически.
3. Добавь действительный `NVIDIA_API_KEY` через «Настроить AI».
4. При записи браузер создаёт WAV PCM mono/16-bit/16-kHz. Backend указывает эти параметры явно в запросе NVIDIA Riva. Подробная причина ответа NVIDIA выводится в консоль сервера и показывается в сообщении STT; `/api/health` отдельно сообщает, установлен ли клиент и настроен ли STT; облачная доступность окончательно проверяется при распознавании.


## Голосовой ввод на русском

1. Запускай приложение через `START.bat`, затем используй адрес `http://127.0.0.1:8765` (не открывай `frontend/index.html` напрямую).
2. В Firefox нажми значок разрешений слева от адреса и установи для микрофона значение «Разрешить». Убедись, что Windows выбрала нужное устройство ввода.
3. Нажми на микрофон один раз — статус должен измениться на «Запись по-русски…». Скажи фразу и нажми микрофон ещё раз, чтобы вставить распознанный текст в поле сообщения.
4. Можно нажать `Enter` во время записи: она остановится, распознанная русская фраза автоматически отправится AI-агенту. `Shift+Enter` по-прежнему добавляет новую строку в поле сообщения.
5. После записи аудио преобразуется в mono PCM WAV 16 kHz и отправляется серверу для NVIDIA Parakeet. Если разрешение микрофона, устройство, формат записи или NVIDIA API недоступны, интерфейс показывает конкретную ошибку.
